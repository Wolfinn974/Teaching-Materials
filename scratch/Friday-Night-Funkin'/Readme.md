# 🎵 Friday Night Funkin'-like (Scratch)

> Build a rhythm game where players press the correct keys in time with the music.

| | |
|---|---|
| **Tool** | Scratch |
| **Target age** | 9 – 15 years old |
| **Level** | Intermediate |
| **Duration** | 3–5 sessions × ~1.5h |
| **Prerequisites** | Variables, conditionals, cloning, timing, and basic animation in Scratch |

---

## 🎯 Learning Objectives

By the end of this project, students will be able to:
- [x] Create a rhythm-based input system
- [x] Spawn moving notes using clones
- [x] Detect key presses with timing windows
- [x] Build a scoring and feedback system
- [x] Synchronize gameplay elements with music
- [x] Organize more complex game logic across multiple sprites

## 📝 Instructor Notes

This project is excellent for teaching:
- timing  
- cloning  
- input detection  
- game feedback systems  

For an efficient classroom version, it is strongly recommended to focus on **one song only**.

A future update will include an additional playable song, as some students asked how to manage multiple tracks in the same project.  
However, for teaching purposes, **one song is enough** and keeps the project much more manageable.

### ⚠️ Common blockers

- Notes are not synced correctly with the music  
- Students detect key presses, but not at the correct timing  
- Too many clones remain on screen and cause lag  
- Score logic becomes messy if hit/miss conditions are not clearly separated  

### 💡 Tips

- Start with only one direction first (for example, one arrow) before adding all inputs  
- Make timing windows visible and easy to understand  
- Keep the first version simple, then add polish later  
- Test often with the music playing — rhythm games break very easily when timing is slightly off  

### 🚀 Possible extensions

- Add multiple songs  
- Add combo or accuracy systems  
- Add visual effects for perfect/good/miss  
- Create different difficulty levels
